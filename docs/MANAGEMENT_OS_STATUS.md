# Management OS 2.9 evidence and scope

This release is a management-role foundation, not completion of the full 25-section transformation brief. Verification is recorded separately from implementation and from human validation.

Implemented: independent primary role and additional lenses, minimal first-run role/priority choices, role navigation with five mobile destinations, sidebar collapse, lazy-loaded editors and centers, v7 compatibility migration, Program components/outcome/benefits/dependencies/roadmap/resource conflicts/currency-separated financial roll-up, ongoing Operation contexts with metric evidence/controls/incidents/cadence reviews, Delivery commitment and observed flow/readiness view, and Today across work with deterministic rules and links back to source contexts. Source registry adds Program Management fifth edition and the official PMI AI standard release notice.

Existing project lifecycle, work status evidence, data recovery, offline PWA, bilingual catalogs and deterministic tools remain shared. Statistical delivery percentiles are suppressed below ten observed cycle samples; missing start dates and operational observations remain unknown. Program projects are references, not copies.

Shared scoped registers now support work, planning, RAID, people, vendors, finance, quality, changes and documents for Program and Operation without persisting a synthetic project. Decision Center adds pending/overdue/upcoming/revisit/ownership/evidence filters, explicit decision timestamps, linked evidence and change history. Recurring operational controls preserve scheduled occurrence and completion history. Decision tools select Project, Program or Operation and persist source scenarios within that context. The landing and author position include all four roles. Programs expose editable milestones and strategic objectives, benefit-to-component links and source links. The palette indexes terms, playbooks, templates and scoped records in a lazy chunk. Role Knowledge provides four problem-led practice scenarios with source and limitation notes. A project-free shell exposes Settings, Today and keyboard commands. Prospective blocked intervals and explicit rework reasons provide Delivery evidence. Operational reviews create linked shared actions and open decisions when explicitly entered. Outcomes are editable and link to deliverables with actual observation/date evidence. Editors show incoming/outgoing relationships. Recurring work creates one next occurrence after completion and preserves missed schedules. Legacy data-source and MARKOVMADE tools select all contexts; ordinal effort scores are not converted to work-hour estimates. Templates and playbooks create shared records in all contexts. Program benefit checks require dated actual observations; missing/future observations stay unknown. Context budget currency is editable. Native registers and observation/completion/review histories render bounded pages while retaining complete arrays and addressable archives.

Reviewed pixel references are recorded in MANAGEMENT_OS_QA.md. Final release requires successful exact-commit cross-browser/export quality gates. Catalog origin panels distinguish original PMWORK practice from referenced standards and explain applicability in four contexts. Further decomposition of legacy CSS/modules and individual editorial enrichment remain follow-up architecture/content work; full editorial certification is not claimed. Human validation remains a separate unfulfilled acceptance gate.

Human evidence: sessions with practicing managers have not been conducted. The protocol covers four roles and three experience levels, identical competitor briefs, unassisted completion, time, wrong turns, assistance, comprehension, confidence and hesitation. NVDA/VoiceOver, physical devices, Windows High Contrast and zoom still require manual review. Automated axe and browser coverage must not be represented as usability completion, WCAG certification or field Core Web Vitals.

Production publication must use an exact-commit export after the complete quality gate passes. A candidate branch or successful local build alone is not deployment evidence.
