# Private decision workflows

Deployment boundary: GitHub Pages only, as requested by the repository owner. PMWORK Private continues to work without an account, backend, trackers, cloud credentials or AI. Team services and OAuth integrations are not enabled or represented as connected.

## Implemented changes

- Today derives typed record references, affected IDs, rule provenance, evaluation date, data gaps and consequences from the existing graph. It includes overdue work, today's deadlines, risk reviews, pending decisions and overdue milestones. A calendar date can be supplied for deterministic replay. Local calendar days replace UTC date truncation.
- Ordinal P × I is labelled a heuristic score, not financial exposure or event probability. Data coverage is no longer labelled forecast confidence.
- My Work requires the configured member's stable identity; an unlinked display name does not establish identity.
- List and Board both use the common status command, preserving prospective transition evidence. External drag payloads cannot change work from another project.
- List renders at most 100 records per page; Board renders at most 40 per column. Filtering covers the full dataset. Group construction is linear rather than repeatedly copying growing arrays.
- Contextual record URLs include record kind and ID, preserve view parameters, and restore on browser Back/Forward. Closing removes the record parameters. The underlying view remains mounted while the editor is open.
- Planning compares two date-shift scenarios, for a work item or all unfinished project work. Optional milestone forecast changes are shown before approval. Apply validates the graph as one mutation; undo appends history rather than erasing it. Stale schedule drafts and stale undo are rejected. Baselines, actual dates, target dates, owners and budgets are preserved.
- Missing cost forecasts remain unknown across Finance, portfolio, health and status drafts. Actual plus committed is not substituted for total forecast. Empty budgets and empty work completion are unknown.
- Production uses the tested static export after both hosting configurations pass, rather than rebuilding an untested artifact. Generated evidence contains the actual build SHA, test counts and bundle measurements. Main requires PR checks, disallows force pushes/deletion, and enforces protection for administrators.

## Evidence sources

The authoritative machine evidence is generated by `scripts/release-evidence.mjs` after the pipeline succeeds. It is uploaded as `release-evidence-<base>-<SHA>` and included in the published `quality-evidence.json`; `release.json` identifies the same production commit. This document intentionally does not hard-code a future verification SHA or claim that a pending run passed.

Browser coverage includes approval/undo, date provenance, typed record navigation, Board status history, missing forecasts and bounded rendering with 1 project / 20 records, 10 projects / 1,000 records, and 50 projects / 10,000 records. Lab filter latency is recorded separately from field INP.

Pixel regression uses fixed clock, bundled fonts, reduced motion and the pinned Playwright Chromium in Linux CI. It covers landing, onboarding, Today, Work, Board, Planning, scenarios, RAID, People, Portfolio, Finance, Control/report drafts, Settings, Documents and Tools in RU/EN, light/dark, desktop/mobile. Expected images are reviewed artifacts checked into the repository. Normal CI compares them; it does not update baselines.

The separate `Review visual references` workflow runs only on the explicit `qa/visual-references` branch. It generates candidate images and compares them twice in fresh browser contexts before exporting them for review. Pixel fixtures block service workers so cached CSS cannot bypass the deterministic font-loading policy; normal offline/PWA tests retain service workers.

## Explicit limits

- Schedule scenarios model date shifts and dependency conflicts. They do not predict resource availability, cost changes, risk realization or deadline probability. Drafts live on the current screen; applied dates and history use normal local persistence.
- Pagination bounds DOM size; this is not virtual scrolling. Large-data lab checks are not field performance measurements.
- Control retains report creation; it has not been replaced with a new report-builder application. Capacity, finance and planning retain the semantics and limitations of their existing data model.
- Local automation rules, role presets, richer collaboration records, recurring work and generalized scenario modeling are not introduced by this release.
- Automated accessibility checks do not certify WCAG conformance. NVDA, VoiceOver, physical devices, Windows High Contrast and human usability still require the protocols in ACCESSIBILITY.md and USABILITY_PROTOCOL.md. No participant results or field CWV are fabricated.

Schema remains v6. This release does not rewrite backups or add a migration. Existing v1–v6 migration, strict unknown-field rejection, IndexedDB primary storage, recovery mirror, snapshots and backup round trips remain part of the verification suite.
