# Bounded benchmark

Reviewed product patterns from Jira, Asana, ClickUp, Notion, Linear, Monday, Smartsheet, Wrike, Trello, and Basecamp. Only implementation-relevant conclusions were retained.

| Pattern | PMWORK decision |
| --- | --- |
| Jira backlog discipline and explicit workflow | Normalized work-item model, readiness warnings, configurable status moves |
| Notion connected docs | Documents reference project entities and export as Markdown |
| Asana approachable overview | One attention panel and a small set of decision-oriented metrics |
| ClickUp breadth | Broad domain coverage, but progressive disclosure rather than one giant screen |
| Linear speed and density | Compact list/board, keyboard-safe controls, restrained visual language |
| Monday visual status | Semantic status with text and color; no rainbow dashboard |
| Smartsheet/Wrike planning | Dense tables, schedule/dependency calculations, controlled finance view |
| Trello direct manipulation | Board drag-and-drop plus visible keyboard/button alternative |
| Basecamp calm communication | Concise copy, clear ownership, low notification noise |

PMWORK does not copy any one product. Its differentiator is the connection between professional guidance, contextual method choice, working project data, and deterministic control tools.

## 2026-09-05 verification and implementation

This pass used current primary product documentation, not claims of exhaustive hands-on comparison:

- [Linear custom views](https://linear.app/docs/custom-views): persist filtered working views; implemented as configurations over original work records.
- [Notion views, filters and sorts](https://www.notion.com/help/views-filters-and-sorts): multiple configurations of the same dataset; adopted for list/board and property display.
- [Jira dependency editing](https://support.atlassian.com/jira-software-cloud/docs/create-or-remove-dependencies-on-your-timeline/): explicit links and schedule relationships; added date conflict evidence.
- [Asana portfolio workload](https://help.asana.com/s/article/how-to-use-portfolio-workload?language=en_US): workload needs a capacity model; PMWORK reports ownership counts separately from hours.
- [ClickUp dashboards](https://help.clickup.com/hc/en-us/articles/6312197753239-Intro-to-Dashboards): related work surfaces; retain focused health/attention instead of adding decorative charts.
- [Monday status columns](https://support.monday.com/hc/en-us/articles/360001269685-The-Status-Column): explicit status labels; retain restrained semantic color.
- [Smartsheet dependencies](https://help.smartsheet.com/articles/765727-enabling-dependencies-using-predecessors): predecessor/lag semantics; apply FS/SS/FF/SF calendar-date checks.
- [Wrike table view](https://help.wrike.com/hc/en-us/articles/360005778794-Table-View-in-Wrike): dense editable tables with display settings; implement visible properties, grouping and sorting.
- [Trello card movement](https://support.atlassian.com/trello/docs/moving-cards-or-lists/): direct card movement plus accessible move controls.
- Basecamp calmness remains a design principle from the brief; the attempted official help-page lookup was unavailable, so no current feature claim is made.

These references support the interaction principles; PMWORK's health thresholds and method-fit percentages remain explicitly labelled product heuristics.
