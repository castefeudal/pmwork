# Human usability validation protocol

Status: **not yet executed**. Automated browser tests are not substitutes for practicing users.

## Participants and setup

Recruit at least five practicing project managers spanning Foundation, Practitioner, and Advanced experience. Use each participant's normal laptop and at least two real mobile devices. Start with an empty browser profile and a fictional but realistic brief; do not expose test selectors or implementation vocabulary. Obtain consent and record no real confidential project data.

## Tasks

1. Create a project, understand the recommended approach, and explain why it was recommended.
2. Identify the single most important action on Today and explain the consequence of not acting.
3. Create a work item with owner, status, due date, acceptance criterion, and estimate; then revise the estimate and find original/current/actual values.
4. Register a qualitative and monetary risk, calculate EMV, save the scenario, and return to the risk.
5. Create and decide a decision record; identify its owner and revisit trigger.
6. Create/edit a milestone baseline and forecast, then explain the displayed variance.
7. Use Deadline Confidence and describe the difference among P50/P80/P90 and its data-quality warning.
8. Find MARKOVMADE, score an intervention, state what not to do yet, create a validation work item, and open it.
9. Find a method from an intent phrase rather than its exact title.
10. Export a backup, make a change, validate the import preview, restore the backup, and explain where the data is stored.

Repeat tasks 2, 3, 6, and 9 at 390px/mobile. Include one keyboard-only run and one screen-reader-assisted run with a participant who regularly uses that technology.

## Measures

For every task record completion, elapsed time, wrong turns, moderator assistance, confidence (1–5), and comprehension answer. Capture the first point of hesitation and the label/action expected by the participant. Suggested targets: ≥90% unassisted completion for core tasks; median ≤180 s for project setup, ≤60 s for work creation, ≤90 s for risk and backup tasks, and ≤30 s to identify Today's priority.

## Release decision

A blocker is any data-loss misunderstanding, inability to recover a backup, inaccessible core action, repeated misreading of unknown as green, or failure to distinguish baseline/forecast/actual. Fix blockers and rerun the affected task. Publish anonymized counts and medians; do not average away failed tasks or describe unexecuted sessions as passed.
